# 서버 전체 점검 스크립트 (읽기 전용)

배포 뒤, 또는 "지금 서버가 진짜 정상인가" 를 한 번에 보고 싶을 때 돌립니다. 아무것도 바꾸지 않고 읽기만 합니다.
결과는 한 줄에 한 항목, `PASS / WARN / FAIL / INFO | 영역 | 항목 | 근거` 로 나옵니다. 2026-09-15 첫 E2E 점검 때 만든 것을 정리했습니다.

| 스크립트 | 어디서 돌리나 | 무엇을 보나 |
|---|---|---|
| `server1.sh` | 서버1 | 컨테이너 상태, 수집기 9개 마지막 성공 시각, Spark 체크포인트 전진, 아카이브 최신 파일, HDFS 건강·목차 사본, 서버2 감시 크론, 네임노드 백업, 자원 |
| `server2.sh` | 서버2 | 컨테이너·헬스체크, 공개 주소 4개 응답, 인증서 남은 날, backend 오류 로그, ml-serving 준비, Redis 키·TTL, MySQL 테이블·백업, Prometheus 대상·Grafana 규칙·발동 알림, 유입량, 브리핑, 자원, 방화벽 |
| `external.sh` | 개발 PC | 바깥에서 열려 있어야 할 포트(80·443)와 막혀야 할 포트(3306·9090·3000·9870·29092·8085), http→https 리다이렉트, 보안 헤더 |

```
# 서버1
bash ~/S15P21E202/infra/scripts/checks/server1.sh | column -t -s'|'
# 서버2
bash ~/S15P21E202/infra/scripts/checks/server2.sh | column -t -s'|'
# 개발 PC (Git Bash)
bash infra/scripts/checks/external.sh | column -t -s'|'
```

읽는 법
- `FAIL` 은 지금 서비스나 데이터에 영향이 있는 것입니다. 절차서(docs/runbooks)로 갑니다.
- `WARN` 은 당장 영향은 없지만 두면 문제가 되는 것입니다. 수집기 한 사이클 실패, 백업 사본 미도착 같은 것입니다.
- `INFO` 는 판정 없이 숫자만 보여 주는 것입니다.
- 지하철 위치 수집기는 새벽 1~5시에 운행이 없어 WARN 이 정상입니다. 버스 위치 수집기는 8시간 주기라 실패 뒤 다음 시도까지 오래 WARN 으로 남습니다.

이 스크립트가 잡아낸 것(2026-09-15): Spark 잡이 9/11 코드로 돌아 Redis TTL 이 119초로 쓰이던 문제, `/healthz` 에 보안 헤더가 빠진 문제.
