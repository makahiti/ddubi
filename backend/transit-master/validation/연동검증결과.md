# 수도권 매핑 프로젝트 연결 검증 — 2026-09-10

기계 결과·원본 해시·테스트별 건수는 [integration-summary.json](integration-summary.json)에 있다.
이번 변경은 기존 매핑 결과를 공통 ID·Collector·Spark·응답·저장·모델 입력 경계에 연결한다.
공간 검증 기준을 낮추거나 과거 검토 규칙을 자동 연장하지 않았다.

## 구현

- canonical-adjacent-v2: 서울 ID 유지, 경기·인천 구성요소에 출처를 붙여 충돌 방지.
- 105,070개 인접 edge 대응표 생성. 원본 순번 단절 2개는 연결하지 않음.
- Collector가 매핑 범위·버전·이유를 Kafka에 보존하고 Spark가 같은 SHA 대응표로 독립 재검증.
- 서울 Redis 키·TTL 유지, 다른 출처는 별도 키 사용. 도착정보를 차량 현재 구간이나 운행시간 정답으로 취급하지 않음.
- 기준선 ID 검증, 응답 품질 집계, 버스 대안별 전체 step 평가와 선택 edge 저장 내부 서비스 구현.
- 모델 승인·학습 ID·입력 지문·시각·전체 edge·평균시간·표본 수 검증 실패 시 전체 step을 카카오 시간으로 fallback.

| Collector 전체 | 71 통과, 1 건너뜀 | 전체 대응표·모호함·Kafka Schema 포함 |
| Spark 관련 최종 회귀 | 19 통과 | 실제 Collector 봉투→Spark→Redis 행 및 전체 대응표 인덱싱 |
| Spark 전체 회귀 실행 | 42 통과, 2 실패 | 기존 날씨 Parquet 2개가 Windows HADOOP_HOME/winutils 부재로 실패 |
| 계약 및 문법 | 통과 | YAML/JSON, Redis 예시↔Java ID, 기준선 입력, 변경 Spark 파일 Python 3.8 AST |

Spark 관련 19개는 전체 회귀와 중복하므로 합산하지 않는다. 전체 회귀 이후 추가한 실배포 대응표 테스트는
최종 관련 회귀에서 통과했다. MySQL 테스트는 실제 Spring 트랜잭션 프록시에서 반복 저장과 두 번째 INSERT
실패 시 기존 행 복원을 검사하도록 작성했지만 이 환경에서 실행하지 못했다.

| 기준일 | BUS step | 차량 대안 | ID 확인·공간 검증 통과 | 기존 v6 ID·순번 유지 |

9월 10일의 나머지는 공간 충돌 8개, 모호함 4개, 미해결 26개다. 이전 대비 27개 감소는 검토일이 지난
규칙을 제외한 결과이며 이번 연결 변경의 악화가 아니다. 각 날짜의 DTO→Mapper→Resolver 결과 281개가
순수 Matcher와 일치했다. 각 날짜의 손상 입력 1,405건에서 잘못된 VERIFIED는 0건이다.
동일 입력 재생 결과와 바탕화면 원본 20개의 SHA도 유지했다. 수도권 전체 정확도나 독립 정답률을 뜻하지 않는다.

## 적용 전 남은 경계

1. V4·마스터 적재·Collector/Spark 대응표 배포는 실행하지 않았다. 같은 버전으로 배포해야 한다.
2. 실제 GPU bundle·학습 ID·공통 전처리 어댑터는 미등록이다. 기본 응답은 predictionReady=false와 카카오 fallback이다.
3. 상위 경로 저장 서비스가 소유권 확인 후 RouteSegmentEdgeWriter를 호출해야 한다. 검색 API 자체는 경로를 저장하지 않는다.
4. 위치 관측의 sectOrd 의미가 검증되지 않아 현재 구간을 임의 확정하지 않는다.
5. 실제 구간시간·지연 상태 계산, GPU 모델 정확도 및 운영 부하 검증은 ID 연결 통과와 별개다.

인프라·Docker·CI·클라이언트·알림은 변경하지 않았다. 운영 초기화·커밋·푸시·배포도 하지 않았다.
호출·소비 예시는 [구간 연결 계약](../../../docs/contracts/metropolitan-segment-integration.md)을 따른다.
