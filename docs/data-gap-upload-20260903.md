## 현재 확인된 공백

1. 버스 구간별 시간대별 통행시간
   - `2022-08`, `2022-09` 원본 ZIP이 각각 약 1 KB로 유효 데이터가 없다.
   - 정규화 파일 기준 `2022-04`는 현재 학습 표본일(5일·20일·공휴일) 조회 결과가 0행이다. 월 전체가 비었다고 단정하지 말고 날짜별 재감사가 필요하다.
   - 2025-01~12 및 2026-01~06은 원본이 서버에 있으나 정규화·학습 반영 여부는 별도로 확인해야 한다.
   - 2026년 경계 주차 ZIP `2026-06-29~07-05`는 파일명과 달리 실제로 `06-29`, `06-30`, `07-02`, `07-03` 4일만 들어 있다. `07-01`, `07-04`, `07-05`는 공식 주차 원본에도 없다.
   - `2026-07-06~08-16`의 나머지 주차 ZIP 6개는 각 7일이 모두 있고, 기존 서버 파일 `segment_time_20260817_0823.zip`과 이어져 원본은 `08-23`까지 확보됐다.
   - 기존 `month=202606` Parquet 안에는 실제 `07-02`, `07-03` 행도 포함돼 있다. 주차 파일을 그대로 추가하면 중복되므로 새 7월 파티션에서는 이 이틀을 제외한다.
   - `2022-08`, `2022-09`는 동일 스키마의 T-Data OpenAPI `TaimsTpssRouteSectionSpeedH/1.0`에서 날짜별 소급 조회할 수 있는 대체 경로를 확인했다. 실행에는 T-Data 활용승인과 `TDATA_API_KEY`가 필요하다.
   - `2026-07`, `2026-08` 주차 원본은 `ybk/data-preparation`에서 기존 12컬럼 학습 스키마와 같은 Parquet로 변환했다. `07-02`, `07-03`을 제외한 뒤 기존 날짜와 중복 0건 및 스키마 동일을 확인하고 공유 정규화 경로에 월 파티션으로 반영했다.
   - 반영된 7월 파티션은 `07-06~07-31` 26일·34,113,754행, 8월 파티션은 `08-01~08-23` 23일·30,143,844행이다. 이는 학습 입력 데이터 반영이며 모델 재학습 완료를 뜻하지 않는다.

2. 고해상도 구간별 실측 도로속도
   - `/home/j-j15e202/raw/`의 `2026-06-01~07-05` 주별 CSV들은 도로속도가 아니라 버스 노선·정류장 구간별 평균 운행시간이다. 도로속도 공백의 근거로 사용하지 않는다.
   - T-Data에서 받은 `1시간 소통정보 (구간별).csv`는 이와 별개의 도로 링크 소통정보이며 실제 범위는 `2026-08-29~09-02`다.
   - T-Data 화면은 날짜 범위를 고르는 과거자료 다운로드가 아니라 최신 파일 한 개를 제공하는 구조라서, 이 파일 하나만으로 과거 도로속도 공백 범위를 확정하거나 소급 확보할 수 없다. 제공기관 과거자료 또는 팀 보관 원본을 별도로 찾아야 한다.
   - 월별 서울시 차량통행속도 XLSX가 2026-01~08을 덮지만 스키마·가공 수준이 다르므로 직접 이어 붙이지 않는다.

3. 지점별 일자별 교통량
   - 2026-01~07은 확보했다.
   - TOPIS 화면에서 `2026-08`은 다운로드가 비활성화돼 있으며 제공시기는 `익월 말일`로 명시돼 있다. 따라서 2026-09-03 현재 공식 게시 전이고 예상 확인일은 2026-09-30이다.
   - 별도 T-Data `1시간 소통정보` OpenAPI는 교통량이 아니라 링크 평균속도이므로 이 공백을 대신 채운 것으로 간주하지 않는다.

4. 교통사고
   - 현재 확보 범위는 `2024-07-18~2025-07-31`뿐이다.
   - 경찰청(UTIC) 돌발 CSV를 추가 확보했지만 범위는 `2020-09-14~2021-11-29`라서 `2021-11-30~2024-07-17` 공백은 여전히 남는다.
   - T-Data `돌발 이력(API)`(`data_id=1067`, `BisTbisClAcdnt/1.0`)은 버스 노선·구간·링크·발생상황을 포함하고 월 1회 갱신된다. 날짜 요청 인자가 없는 전체 이력형 API이므로 별도 활용신청 후 전체 페이지를 받아 실제 보유기간을 먼저 감사한다.
   - T-Data의 `서울시 실시간 돌발 정보` API는 이후 시점부터 누적할 수 있지만 과거 누락을 소급 복원하지는 못한다. `2025-08` 이후는 해당 API/수집기의 지속 누적 대상으로 둔다.

5. 배차·차량 실제 통과 이력

   - 배차 집계나 정류장별 시간대 승하차 데이터는 동일 차량의 정류장 통과 시각 정답을 대체하지 않는다.

6. 발표 시점 기준 기상예보

   - `collector/src/download_weather_forecast_archive.py`는 발표시각별 JSONL을 재개 가능한 형태로 저장한다. 실제 수집에는 해당 API 활용승인과 `KMA_API_KEY` 또는 `DATA_GO_KR_API_KEY`가 필요하다.
   - EC2 수집기는 과거분과 별개로 지금부터 실시간 발표본을 계속 누적한다.

## 처리 원칙

- 파일명에 월이 있어도 실제 날짜와 00~23시 컬럼/행을 검사한다.
- 서로 다른 범위·스키마의 도로속도 파일을 하나의 연속 시계열로 간주하지 않는다.
- 예측 피처는 `feature_available_at <= prediction_base_at`을 만족해야 한다.
- GPU 서버는 전처리·학습용으로 사용하고, 지속적인 실시간 수집은 EC2 수집기에서 수행한다.
