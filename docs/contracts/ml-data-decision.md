# DDUBI 머신러닝 학습·예측 데이터 결정사항

- 결정일: 2026-09-08 (Asia/Seoul)
- 근거: 사용자가 이 대화에서 정리한 전체 원천 데이터 표와 실시간 수집 표를 기준으로 결정하고 저장하도록 요청함.
- 상태: **목표 수집 범위와 학습·예측 일치 원칙 확정. 데이터 확보·연결·재학습 완료를 의미하지 않음.**
- 용도: 수집팀 전달 및 이후 ML 작업의 기준 문서. 기계 계약·모델별 입력 스키마는 구현 시 별도 검증한다.
- 이번 저장은 문서화만 수행하며 GPU 서버, 수집기, 모델, 노트북, 운영 계약은 변경하지 않는다.

## 1. 확정한 방향

1. 전체 경로를 버스 이동, 버스 대기, 지하철 이동, 지하철 대기, 환승 이동, 일반 도보로 구분한다.
2. 일반 도보는 사용자 결정대로 **경로 API 도보시간을 fallback으로 사용**한다. 일반 도보 ML 학습은 이번 목표에서 제외한다.
3. 버스 등의 ML은 실제 정답 확보와 검증을 전제로 활용한다. **2026-09-10 사용자 결정으로 지하철 대기·이동은 우선 시간표와 실시간 도착·위치로 계산하고 ML을 사용하지 않는다.** 기존 표의 지하철 학습 입력/정답은 향후 검증 자료 범위이며 현재 ML 구현 대상으로 해석하지 않는다. 지하철 구현·미확보 입력은 [subway-timing.md](subway-timing.md)를 따른다.
4. 사용자는 **직선거리를 입력에서 제외**하기로 했다. 기존 v9에는 포함되어 있으므로 예측 때만 빼지 말고 재학습한다. 정류장 좌표와 실제 환승 통로 거리는 별도 정보이며 일괄 삭제하지 않는다.
5. 예측 입력은 **경로·예측 날짜/시각 + 마스터·달력 + 과거 통계 + 이용 가능한 최신 관측·예보**로 구성한다. 모든 값을 실시간 API에서 받을 필요는 없다.
6. 학습·예측은 같은 ID 체계, 단위, 코드 체계, 집계 기간과 전처리 버전을 사용한다. 실제 확보할 수 없는 입력은 양쪽에서 제외하거나 검증된 동일 결측 처리 규칙을 적용한다.
7. 최종 학습 데이터와 테스트 데이터는 **7:3**으로 분리한다. 시간 순서·날짜 경계를 보존하므로 실제 행 비율의 작은 차이를 기록한다. 모델 선택용 내부 검증은 학습 70% 안에서만 분리하고, 최종 학습에는 다시 합친다. 테스트 30%는 학습·모델 선택에 사용하지 않는다.

## 2. 학습 데이터와 결과를 얻기 위한 입력

아래는 구성요소별 목표이다. 하나의 v9 모델에 모두 넣는다는 뜻이 아니다. 실제 결과값은 예측 요청의 입력이 아니라 학습 정답이다.

| 예측 대상 | 학습할 때의 입력 | 실제 예측할 때의 입력 | 학습 정답 / 출력 |
|---|---|---|---|
| 버스 구간 이동 | 당시 노선·정류장·순번·좌표, 날짜/시간·휴일, 당시 이용 가능한 날씨·과거 이력·수요·교통 정보 | 대상 구간의 같은 식별자·좌표, 진입 예상시각·휴일, 이용 가능한 동일 기준의 최신 정보·과거 통계 | 구간 소요시간(초). 평균 관측과 개별 차량 관측을 구분 |
| 버스 대기 | 당시 정류장 도착시각, 탑승할 노선·방향, 당시 도착예측·차량 위치 | 정류장 도착 예상시각, 노선·방향, 예측 시점에 확보한 도착·위치 정보 | 정류장 도착부터 실제 탑승까지(초) |
| 지하철 대기 | 당시 승강장 도착시각, 역·노선·방향·행선지, 시간표, 당시 도착·위치 정보 | 승강장 도착 예상시각과 동일 항목의 가용 정보 | 승강장 도착부터 실제 탑승까지(초) |
| 지하철 이동 | 승차·하차역, 노선·방향·일반/급행, 날짜/시간, 적용 시간표와 당시 운행 상태 | 대상 역·노선·방향·일반/급행, 예상 이용시각, 적용 시간표와 가용 운행 상태 | 실제 탑승부터 하차까지(초). 열차 운행 기록으로 만든 역간 시간과 정의 구분 |
| 환승 이동 | 하차 위치·다음 승강장, 환승 방향·통로 거리·기준시간, 당시 시간대 등 | 동일 기준의 환승 경로 정보와 예상 이용시각 | 하차부터 다음 승강장 도착까지(초), 다음 차량 대기는 제외 |
| 일반 도보 | 별도 ML 학습하지 않음 | 경로 API의 해당 도보 구간시간 | API 시간 사용, 출처 표시 |

앞 구간의 도보·대기·이동시간을 반영해 다음 구간 진입 예상시각을 계산한다. 경로 API 총시간과 구성요소를 동시에 더하거나, 환승 이동과 다음 차량 대기를 중복 합산하지 않는다. 현재 관측을 미래 구간의 실제 상태로 취급하지 않는다.

2026-09-10 구현: 버스 대기는 현재 확보한 공식 도착예측으로 계산하고 지하철 대기는 시간표·실시간으로 계산한다.
별도 대기 ML 학습 완료를 뜻하지 않는다. 필드·단위 수정, 실제 적용 조건과 관측 부족 처리는 [대기시간 계약](transit-waiting.md)을 따른다.

## 5. 학습·예측 일치 및 결측 방지 기준

- 수집팀은 원천 응답과 이력을 보존한다. ML 파트는 공통 전처리로 ID 매핑, 날짜 파생, 공간·시간 결합, 과거 통계를 계산한다.
- 발생/관측시각, 집계 대상 기간, 발표·공개시각(확인 가능한 경우), 수집시각, 출처, 원본 단위, 마스터 버전을 분리해 저장한다. 공개시각 미확인은 추측하지 않는다.
- 학습 입력에는 당시 예측 시점까지 실제 확보 가능했던 자료만 사용한다. 미래 정답, 사후 수정 자료, 뒤늦게 공개된 통계와 실제 미래 날씨를 섞지 않는다. 예보는 발표시각별 이력을 보존한다.
- 날짜·시간 기준은 Asia/Seoul, 요일은 1=일요일~7=토요일, 소요시간은 초를 사용한다. 원본 코드·거리·풍속·적설 등의 단위 변환 규칙을 버전으로 고정한다.
- ID가 모호하거나 결측이면 임의 이름 매칭·임의 ID 생성으로 성공 처리하지 않는다. 데이터 제공자 ID와 내부 구간 ID를 구분한다.
- 결측을 무조건 0으로 채우지 않는다. 실제 0과 누락을 구분하고, 항목별 결측률·매핑률·최신성·표본 수를 기록한다.
- 안정적으로 확보 불가능한 특성은 양쪽에서 제외하고 재학습한다. 일시적 결측은 같은 검증된 처리 규칙과 결측 표시를 사용하며, 핵심 매핑 실패 시 명시적 fallback 또는 예측 불가로 처리한다.
- 이 목록을 정했다고 결측 0건이나 특정 오차를 보장하지 않는다. 최종 필드명·필수 여부·허용 지연·집계 기간·fallback은 실제 자료 확인과 테스트로 확정한다.

## 6. 현재 상태와 후속 검증

- 대화에서 확인한 기존 v9는 **시간대별 버스 구간 평균 소요시간** 모델이다. 전체 경로 또는 개별 차량·사용자의 실측시간 모델로 부르지 않는다.
- 대화에서 확인한 경로 비교 입력은 기본 57개 중 16개만 채워지고 41개가 결측이었다. 이는 당시 비교의 상태이며 이후 모든 실행에 대한 보장은 아니다.
- 버스·지하철 도착/위치, 사고·통제·집회를 수집하는 것만으로 기존 v9의 결측이 채워지지 않는다. 신규 특성은 이력·정답을 연결하여 재학습·검증해야 한다.
- 지하철 위치 API의 상태 시각은 정밀한 실제 도착·출발 순간을 보장하지 않는다. 이를 운행 정답으로 재구성하면 수집 간격·지연·오차 범위를 검증하고 추정 라벨로 표시한다.
- 시간표는 예정시간, 도착 API는 예측값, 환승 기준시간은 참고값이다. 실제 이용시간과 동일한 정답으로 취급하지 않는다. 환승 집계자료의 단위와 대기 포함 여부도 검증한다.
- 정답이 확보되지 않은 모델은 학습을 진행했다고 표현하지 않는다. 그동안 API/시간표 기반 구성요소는 ML 결과와 구분해 표시한다.
- 검증은 미래 기간을 분리하고, 경로 API 단독 / 기존 모델 / 실시간 결합 방식의 같은 표본을 비교한다. API와 모델의 예상시간 차이만으로 정확도를 판정하지 않는다.
- 일반 도보 fallback, 직선거리 제외와 입력 범위 변경은 실제 적용 시 모델 버전과 함께 기록한다. 이번 문서 저장으로 적용 완료된 것은 아니다.

## 7. 이후 작업 시 유지할 사용자 제약

- DuckDB는 사용·생성·수정하지 않는다.
- GPU 학습은 서버에서 수행하고 **GPU device 0만 사용**한다. 다른 GPU는 사용하지 않는다.
- 전처리 CPU 병렬도는 최대 16개 범위에서 메모리·서버 부하를 함께 제한한다.
- 서버 data 폴더는 원천·정규화 데이터용으로 구분하고, 결과·실행 상태는 j-moo에서 찾기 쉽게 제공한다. 실제 경로 확인 없이 이동·삭제하지 않는다.
- 이 문서 저장은 수집 시작, 모델 재학습, 파일 정리, 커밋·푸시·MR·배포의 승인이 아니다.
