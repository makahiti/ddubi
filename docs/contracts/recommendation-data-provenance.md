# 추천 계산값의 출처와 사용 제한

> 합의: 2026-09-10, 백엔드 ↔ 분산팀
> 대상: `TravelTimeEstimator` 가 만드는 구간별 소요시간, `route_request.raw_response`

추천이 내놓는 숫자가 **어디서 왔고, 어디에 쓰면 안 되는지**를 적는다.
이 문서가 없으면 다음 사람이 서빙용 추정치를 학습 정답으로 되먹인다.

---

## 1. 출처 네 가지

| 출처 | 무엇인가 | 학습 정답·기준선 표본으로 |
| --- | --- | --- |
| `PREDICTION` | 예측 서비스(Python)가 준 버스 구간 소요시간 | ❌ 모델 출력이다 |
| `BASELINE` | `baseline_serving` 의 평소값 p50 | ❌ 이미 집계된 결과다 |
| `ROUTE_API` | 외부 경로 API step 시간을 **그대로** | ❌ 외부 추정치다 |
| `ROUTE_API_SPLIT` | 위 step 시간을 edge 들에 **균등 분배** | ❌ **관측이 아니라 배분값이다** |

**어느 것도 학습 정답이 아니다.** 되먹이면 모델이 자기 출력을 배운다.
코드에서는 `EstimateSource.isSynthetic()` 이 배분값을 걸러 준다.

## 2. 판단 단위는 step 이다 — 부분 혼합 금지

외부 경로 API 가 주는 이동 구간(카카오 step) 하나가 판단 단위다.
그 안의 edge 들은 **같은 출처**를 쓴다.

```
step 의 edge 5개 중 3개만 예측이 됐다  →  5개 전부 폴백
```

한 step 안에서 일부만 ML 값으로 바꾸지 않는다. step 시간은 edge 다섯 개 **전체**를
덮는 값이라, 셋이 다른 출처를 쓰고 있으면 남은 둘에 나눠 줄 시간을 정할 근거가 없다.
부분 혼합을 하려면 별도 정책과 검증이 필요하다.

기준선도 같다 — edge 하나라도 비면 그 step 전체가 경로 API 로 내려간다.

## 3. 균등 분배의 성질

* **합은 원본과 정확히 같다.** 정수 초로 저장하므로 나머지를 앞쪽 edge 부터 1초씩
  더 준다(최대잉여법). 그냥 나누면 `900 ÷ 7 = 128` 씩 896초가 되어 **4초가 사라진다.**
  구간이 많은 경로에서 이 오차가 쌓이면 출발 시각이 앞당겨지고 그만큼 사용자가 늦는다.
* **개별 edge 값은 사실이 아니다.** 정류장 간 거리가 다른데 같은 시간을 준 것이다.
  "구간 A 가 3분 걸렸다" 고 읽으면 안 된다. 합만 의미가 있다.
* **edge 가 없으면 나누지 않는다.** 도보이거나 서울 마스터 매핑에 실패한 step 은
  경로 API 시간을 그대로 쓴다 (`ROUTE_API`).

## 4. ⚠️ `route_request.raw_response` 를 저장하지 않는다 — 재현 한계

DDL 주석은 이 열을 "외부 응답 원본 전체 — 재현성 확보용" 이라고 한다.
**지금은 `NULL` 로 남는다.** `PublicTransitRouteClient` 가 카카오 원본을 노출하지 않고
매핑된 내부 모델만 돌려주기 때문이다.

열이 nullable 이라 **저장은 되지만, 저장이 된다는 것과 재현이 된다는 것은 다르다.**
원본이 없으면 다음을 완전히 재현할 수 없다.

* 카카오 응답 **파싱** 이 잘못돼 생긴 문제
* 서울 마스터 **매핑** 이 잘못돼 생긴 문제 — 우리가 안 뽑은 필드가 원인이면 특히
* "그때 카카오가 정말 이 경로를 줬나" 자체의 확인

우리가 뽑아 쓴 필드만 남으므로, **뽑지 않은 필드 때문에 생긴 문제는 사후 조사가
불가능하다.** 원본을 채우려면 클라이언트가 원문을 함께 돌려주도록 고쳐야 한다.

## 5. 실시간 보정은 위 네 출처와 다르다

Redis `segment:status` 의 `delaySeconds` 는 기본 소요시간의 대체재가 아니라
그 위에 얹는 **보정**이다. 배분값이 아니라 관측이므로 edge 단위로 붙는다.

다만 **진입 예상시각이 그 값의 `validUntil` 안에 들 때만** 더한다.
한 시간 뒤에 지나갈 구간에 지금의 정체를 얹으면 예측이 아니라 착각이 된다
(ML 결정 문서 2026-09-08 의 "현재 관측을 미래 구간의 실제 상태로 취급하지 않는다").
