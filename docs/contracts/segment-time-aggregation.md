# 구간별 이동시간 합산 계약

2026-09-18 · S15P21E202-74 · 내부 단위: 초, 거리: m

이 문서는 사용자 확정 정책에 따라 이전의 총시간 잔여 배분·시간 분해 승인 조건을 대체한다. 운영 배포나 모델 승인을 의미하지 않는다.

## 입력과 처리 순서

1. 카카오 대중교통 후보의 순서·탑승 구간·환승 WALK를 유지한다.
2. 출발지→첫 승차지, 마지막 하차지→목적지를 카카오 도보 API로 조회한다. 끝 도보가 원본에 없으면 평가용 WALK를 만든다. 총시간과 step 합의 차이는 호출 조건이 아니다.
3. 앞 구간의 종료시각을 다음 구간 진입시각으로 사용한다. 계산 가능한 승차대기만 별도 WAIT로 합산한다.
4. BUS는 모든 인접 edge의 적용 가능한 ML 예측 합을 사용한다. 일부 edge라도 실패하면 해당 BUS step 전체를 카카오 시간으로 대체한다. 과거 평균 서비스로 다시 대체하지 않는다.
5. SUBWAY는 시간표·운행정보 계산의 대기와 탑승을 사용한다. 계산 불가하면 해당 카카오 SUBWAY step 시간을 사용하고 대기는 제외한다. 시간표에 탑승 후보가 없는 경우도 원본 예상으로 반환하되 `SUBWAY_NO_BOARDABLE_TRAIN` 근거를 보존한다. 이는 운행 가능 보장이 아니다. 별도로 확인한 구간 통제는 계속 차단한다.
6. 환승 WALK는 카카오 대중교통의 해당 step 시간을 그대로 사용한다.
7. 합산 결과로 출발시각을 평가한다. 계획 출발+소요시간이 일정 시작보다 이르면 계획 출발 유지, 같거나 늦으면 일정 시작 600초 전 도착을 목표로 출발을 역산·재평가한다.

`T = 접근 도보 + 계산된 대기들의 합 + 선택된 버스/지하철 탑승시간들의 합 + 환승 WALK + 이탈 도보`

카카오 전체 소요시간과 step 합의 차이를 도보·대기에 배분하거나 다시 더하지 않는다. 대기 계산 실패는 `WAIT_TIME_EXCLUDED`로 기록하며 관측된 대기 0초로 표시하지 않는다. 이후 구간의 시간대·환승 계산에도 위 합산 시각을 사용한다.

## 도보 응답과 기존 수식

- API: Kakao Map `GET /v2/routing/walk`.
- 좌표: 일정 출발지·목적지와 대중교통 경로 승하차 끝점. 검증된 마스터 좌표를 사용하는 설정도 유지한다.
- 기본 시간: `route.properties.totalTime`.
- 보정 입력: `route.legs[].steps[].properties.guidance`, `distance`.
- 실제 안내 `횡단보도 이용`처럼 `횡단보도`를 포함하고 길이가 `0 < L <= 100m`인 step마다 기존 경험식 `B(L)=10×ceil((116.91249+1.259×L)/10)`을 더한다.
- 명시된 무신호 안내, 길이 결측·범위 밖은 가산하지 않는다. guidance 자체는 신호 설비나 현재 신호 상태를 증명하지 않는다. 보정값은 계획 여유이며 실시간 대기 예측이 아니다.
- 예: 기본 452초, 횡단보도 38m → 여유 170초 → 도보 622초. 복수 횡단 step은 각각 합산한다. 환승 도보에는 적용하지 않는다.
- 실패 시 기존 WALK step이 있으면 그 시간을 보존한다. 원본에도 없는 끝 도보는 `WALK_ENDPOINT_DURATION_UNAVAILABLE`로 기록하며 확보된 구간만 남는다. 이 경우 합산값은 완전한 문전 간 시간으로 해석할 수 없다.
- 같은 좌표 요청은 한 평가의 캐시를 공유한다. 기존 호출 예산·429 backoff·좌표 검증은 유지되므로 모든 후보의 외부 호출 성공을 보장하지 않는다.

공식 응답 구조: https://developers.kakao.com/docs/ko/kakaomap/rest-api#walking

## 모델 적용과 탐색 한계

SHADOW는 예측을 기록하고 카카오 BUS 시간을 사용한다. TEST_APPLY·PRODUCTION은 기존 모드별 적격 검사를 유지한다. 시험 등급이라는 이유만으로 이미 적용한 숫자를 폐기하지 않지만 모델 승인 상태는 승격하지 않는다.

고정 구간 합은 직접 역산한다. 동적 탐색은 기존 시간·횟수 예산을 유지한다. 동적 탐색 미완료·모델 버전 변경 시 원본 구간 합으로 재평가하는 기존 복구 경로가 남아 있으며 사유를 기록한다.

## 손계산 검증 예

접근 622초 + 버스 ML 300초 + 대기 결측(제외) + 환승 120초 + 지하철 원본 600초 + 이탈 180초 = 1,822초. provider 전체 시간은 위 합과 무관하다. 버스 ML 실패 시 버스 원본이 420초라면 총 1,942초다.

회귀 테스트는 끝 도보 누락·원본 잔여시간 존재, 도보 API 장애, 버스 일부 edge 실패, 대기 결측·대기 성공+원본 탑승, 지하철 계산 실패, 신호 여유 수식, 조건부 출발 역산을 포함한다. 서버 배포·실제 API 권한 검증은 로컬 단위 테스트와 구분한다.
