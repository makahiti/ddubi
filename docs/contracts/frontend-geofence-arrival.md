## 서버는 준비돼 있습니다 — 손댈 것 없습니다

`actualArrival` 을 받을 뿐, 그 값이 버튼에서 왔는지 GPS 에서 왔는지 서버는 구분하지 않습니다.
지오펜스에 필요한 것도 이미 다 나갑니다.

| 필요한 것 | 어디서 |
| --- | --- |
| 목적지 좌표 | `GET /schedules` 응답의 `destination.lat` / `destination.lng` |
| 도착 목표 시각 | 같은 응답의 `arriveBy` |
| 감시 대상 판별 | 같은 응답의 `status == "UPCOMING"` |
| 도착 보고 | `POST /schedules/{id}/arrival` |

```json
"destination": { "name": "광화문", "lat": 37.5716229, "lng": 126.9767879 }
```

## 🔴 가장 중요 — `DateTime.now()` 를 보내지 마세요

**지오펜스 이벤트에 찍힌 시각을 보내야 합니다.**

OS 는 배터리를 아끼려고 위치 이벤트를 모아서 전달합니다. **수 분 늦게** 콜백이 뜨는 일이
흔합니다. 그때 `now()` 를 보내면 실제로는 정시 도착인데 **지각으로 기록**됩니다.

```dart
// ❌ 이렇게 하면 리포트가 틀어집니다
await api.reportArrival(id, actualArrival: DateTime.now());

// ✅ 이벤트가 발생한 시각을 그대로
await api.reportArrival(id, actualArrival: event.timestamp);
```

서버는 **과거 시각을 제한 없이 받습니다.** 미래만 1분까지 허용합니다(기기 시계 오차 감안).
그래서 오프라인이었다가 다음 날 올려도 **그때 시각으로 정확히 기록**됩니다.

> 판정 경계가 10분입니다(`목표 10분 이상 전 = ON_TIME`, `그 안쪽 = TIGHT`, `목표 이후 = LATE_RISK`).
> 이벤트가 3분 늦으면 `TIGHT` 이 `LATE_RISK` 로 넘어갑니다. 왜곡이 바로 눈에 보이는 크기입니다.

## 요청 형식

```
POST /api/v1/schedules/{scheduleId}/arrival
Authorization: Bearer {accessToken}

{ "actualArrival": "2026-09-07T18:55:12", "locationConsent": true }
```

- `locationConsent` 는 **필수**입니다. 이번 건에 위치 기반 값을 쓸지에 대한 **거부권**입니다
- 서버는 계정 동의(`user.historyConsentedAt`)와 이 값이 **둘 다** true 여야 실측을 저장합니다
- 둘 중 하나라도 없으면 **200 이지만** `actualArrival` · `result` 가 `null` 로 옵니다.
  일정은 그래도 `DONE` 이 됩니다 — 실패가 아닙니다
- **멱등입니다.** 같은 일정을 여러 번 보고해도 기록이 늘지 않고 판정만 갱신됩니다.
  재시도를 마음 놓고 하세요

응답에서 쓸 값:

```json
{ "scheduleId": 12, "status": "DONE", "reportDetailId": 1,
  "actualArrival": "2026-09-07T18:55:12", "result": "ON_TIME",
  "plannedDepart": null, "proxyDurationMin": null, "mainCause": null }
```

`result` 는 `ON_TIME` / `TIGHT` / `LATE_RISK`.
뒤 세 개는 추천 엔진(Phase 3) 전까지 **항상 null** 입니다.

## 구현 시 걸릴 것들

### 1. 백그라운드 위치 권한은 2단계입니다

Android 10+ 는 "앱 사용 중 허용"과 **"항상 허용"이 별개**이고, 후자는 시스템 설정 화면에서
따로 받아야 합니다. 앱 안에서 한 번에 받을 수 없습니다.

**거부해도 앱이 멀쩡히 돌아가야 합니다.** 거부 상태면 지오펜스가 조용히 아무 일도 안 하므로,
그 사실을 사용자에게 알려주는 화면이 필요합니다.

### 2. 배터리 최적화 예외

삼성·샤오미는 백그라운드 작업을 공격적으로 종료합니다. 국내 기기 대부분이 해당됩니다.
`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 안내가 필요합니다.

### 3. 재부팅하면 지오펜스가 전부 날아갑니다

`BOOT_COMPLETED` 리시버에서 다시 등록해야 합니다. 이걸 빠뜨리면 "어제까진 됐는데
오늘 안 되네" 가 됩니다.

### 4. 등록·해제 시점

- **등록**: 일정 생성·수정 시, 그리고 앱 시작 시 `GET /schedules?status=UPCOMING` 로 재동기화
- **해제**: 도착 보고 성공 시, 일정 취소 시
- **개수 제한**: 앱당 100개입니다. 반복 일정이 14일치 선생성되므로 넘칠 수 있습니다.
  **가까운 일정 위주로만** 등록하세요 (예: 앞으로 24시간 이내)

### 5. 반경

100~150m 를 권합니다. 그보다 작으면 도심 GPS 오차로 안 잡히고, 크면 근처만 지나가도 울립니다.

### 6. 백그라운드에서의 인증

앱이 꺼진 상태에서 API 를 부르려면 백그라운드 isolate 에서 토큰을 꺼내 쓰고, 만료 시
갱신까지 해야 합니다. 액세스 토큰 1시간 / 리프레시 14일입니다.

**갱신에 실패하면 보고를 버리지 말고 큐에 쌓아두세요.** 서버가 과거 시각과 재시도를 모두
받으므로, 다음에 앱이 켜졌을 때 올리면 됩니다.

## 시연 준비 체크리스트

시연은 미리 설정해둔 기기로 하기로 했습니다. 그 기기에서 **미리** 해둘 것:

- [ ] 위치 권한 **"항상 허용"**
- [ ] 정확한 위치(precise location) 켜기
- [ ] 배터리 최적화 **제외**
- [ ] 로그인 상태 유지 (토큰 유효)
- [ ] 시연 직전 재부팅했다면 **지오펜스 재등록 확인**

> 시연 기기 하나로 커버되지만, **다른 기기에서는 위 설정 없이 동작하지 않습니다.**
> 평가나 사용자 테스트에서 다른 폰을 쓸 일이 생기면 미리 말씀 주세요 —
> "앱을 열었을 때 도착 여부를 묻는" 보조 흐름은 백그라운드 권한 없이 하루 이틀이면 붙습니다.

### 테스트 방법

실제로 걸어다니지 않아도 됩니다.

- Android 에뮬레이터: Extended controls → Location 으로 좌표 주입
- 실기기: 개발자 옵션 → 모의 위치 앱 설정
- 서버 쪽만 확인하려면 `backend/http/reports.http` 로 직접 호출해도 됩니다

## 기획에 확인이 필요한 것

지금 동의 문구(`historyConsentedAt`)는 **"도착 기록을 남기는 데 대한 동의"** 입니다.
백그라운드 상시 위치 추적은 그보다 **큰 동의**라, 문구를 다시 쓰고 동의를 새로 받아야 할
수 있습니다. 기획에 확인 부탁드립니다.

## 요약

1. 서버는 그대로 쓰면 됩니다. 좌표·목표시각·상태가 이미 `GET /schedules` 로 나갑니다
2. **`now()` 가 아니라 이벤트 시각을 보내세요** — 이것 하나가 판정 정확도를 좌우합니다
3. 권한 거부·재부팅·100개 제한은 반드시 걸립니다. 미리 처리해 두세요
4. 실패한 보고는 버리지 말고 큐에 — 서버가 과거 시각과 재시도를 받습니다
