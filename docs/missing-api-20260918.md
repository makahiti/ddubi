# 아직 구현되지 않은 API 정리 (2026-09-18)

앱과 서버를 맞춰 보고, 앱에 "준비 중"으로 막혀 있는 화면이 어떤 API 를 기다리는지 정리했다.
기준 커밋: `be/dev ad9085d`.

## 진행 (2026-09-18 16:30 갱신)

| 항목 | 상태 |
|---|---|
| 알림 삭제 | **완료** — 서버·앱 양쪽 |
| 비밀번호 변경 | **완료** — 서버·앱 양쪽 |
| 이메일 변경 | **완료** — 서버·앱 양쪽 |
| 네이버 연결 | **완료** — 아래 정정 참고 |
| 스탬프 도장판 | 남음. 시연 필요 여부부터 결정 |

**아래 4번 네이버 항목은 틀렸다.** 외부 협의 대기가 아니라 우리 서버에 인가 코드를 받는
입구가 없었을 뿐이다. 자세한 것은 그 절의 정정 상자에 적었다.

덤으로 찾은 것: 서버2 `infra/.env` 에 자동 알림 스위치가 켜져 있는데도 알림이 0건이었다.
compose 가 그 값을 backend 컨테이너로 넘기지 않아서다. 고쳐 두었고 배포하면 적용된다.

---

## 3줄 요약

1. 앱이 부르는데 서버에 없는 경로는 **없다.** 연결된 것은 전부 동작한다.
2. 막혀 있는 곳은 **앱이 아예 호출하지 않고 "준비 중" 문구만 띄우는 화면 4개**다. 서버에 해당 API 가 없어서다.
3. 그중 **알림 삭제**와 **비밀번호·이메일 변경**이 사용자가 실제로 누르는 자리라 우선순위가 높다.

---

## 1. 알림 개별 삭제 — 서버에 없음

| 항목 | 내용 |
|---|---|
| 앱 위치 | `notification_center.dart` — 선택 모드에서 삭제를 누르면 "선택한 알림 삭제 기능은 준비 중이에요" |
| 서버 현황 | `NotificationController` 에 조회 2개, 읽음 처리 2개만 있고 **삭제가 0개** |
| 필요한 것 | `DELETE /api/v1/notifications/{id}` 와 여러 건 삭제 |

앱에는 이미 선택 모드와 삭제 버튼까지 만들어져 있다. 서버만 생기면 문구를 지우고 바로 연결된다.

**생각할 점**: 진짜 지울지, 숨김 표시만 할지 정해야 한다. 알림은 발송 기록이기도 해서 지우면 "언제 무엇을 보냈는지"가 사라진다. 사용자에게만 안 보이게 하는 편이 안전하다.

## 2. 계정 관리(비밀번호·이메일 변경) — 서버에 없음

| 항목 | 내용 |
|---|---|
| 앱 위치 | `screens.dart` 계정 관리 — 비밀번호 확인 뒤 "계정 연결 API 연동 후 제공될 예정이에요" |
| 서버 현황 | `UserController` 는 조회·수정·탈퇴만 있고, 수정은 닉네임·알림설정·교통수단 선호뿐. **비밀번호 변경, 이메일 변경 없음** |
| 필요한 것 | 비밀번호 변경, 이메일 변경(인증 포함) |

앱은 비밀번호 재확인 대화상자까지 만들어 두고 그다음이 비어 있다.

**생각할 점**: 이메일 변경은 인증 절차가 필요하다. `POST /auth/email/verification` 이 이미 있으니 그 흐름을 재사용할 수 있다.

## 3. 네이버 계정 연결 — ~~협의 대기~~ **정정: 우리 코드 문제였다**

> **정정 (2026-09-18)**
> 처음에 "외부 협의 대기" 라고 적었는데 틀렸다. 네이버 **로그인**은 서버·앱 모두 완성돼
> 실제로 네이버로 가입한 계정도 있다. 막힌 것은 마이페이지의 연결 칸 하나뿐이었고,
> 원인은 주고받는 물건이 안 맞는 것이었다.
>
> | | 앱이 받아오는 것 | 연결 입구가 받던 것 |
> |---|---|---|
> | 카카오 | 액세스 토큰 | 액세스 토큰 ✅ |
> | 구글 | ID 토큰 | ID 토큰 ✅ |
> | 네이버 | **인가 코드** | 받는 길 없음 ❌ |
>
> 네이버는 앱이 SDK 가 아니라 웹 창으로 로그인해서 토큰이 아니라 코드만 돌아온다.
> `POST /auth/social-links` 가 인가 코드도 받도록 고쳤다. 코드를 사용자 정보로 바꾸는
> 부품은 로그인(AUTH-003)이 쓰던 것을 그대로 쓴다. 앱의 "준비 중" 칸도 카카오·구글과
> 같은 연결 버튼으로 바꿨다.

| 항목 | 내용 |
|---|---|
| 앱 위치 | `screens.dart` 소셜 연결 목록 |
| 서버 현황 | `POST /auth/social-links`, `DELETE /auth/social-links/{provider}` |
| 막혔던 이유 | 연결 입구가 인가 코드를 받지 않았다 |

## 4. 스탬프 도장판 — 서버에 없음

| 항목 | 내용 |
|---|---|
| 앱 위치 | 더보기 — "도장판은 실제 미션 데이터 연동 후 제공될 예정이에요" |
| 서버 현황 | 미션·스탬프 관련 코드가 **전혀 없다** |
| 필요한 것 | 미션 정의, 달성 판정, 조회 API |

오늘 오전에 데모 데이터를 운영 빌드에서 걷어냈다. 지금은 안내 문구만 나온다.

**생각할 점**: 범위가 가장 크다. 시연에 필요한지부터 정하는 게 좋겠다.

---

## 5. 그 밖에 확인한 것

- **앱이 부르는데 서버에 없는 경로: 없음.** 앱의 모든 호출이 실제 엔드포인트와 맞는다.
- **서버에 있는데 앱이 안 쓰는 것**: 내부용(`/internal/*`)과 개발용(`/api/v1/dev/*`)뿐이다. 각각 서버 간 통신과 시험 발송용이라 정상이다.
- 홈(`/home`), 이동 기록(`/history`), 리포트(`/reports`), 장소(`/places`), 반복 일정(`/schedule-repeats`) 은 서버와 앱 양쪽에 다 있다.
