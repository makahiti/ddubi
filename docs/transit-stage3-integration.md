# 3단계 — 새 BE·마스터 연동

> 후속 진행: 사용자 승인으로 전체 서버 적재·과거 평균 실제 계산 연결을 진행한다.
> 전체자료/실행 절차는 `transit-stage3-deployment.md`, 계산 정책은 `contracts/bus-historical-fallback.md`.
> 아래 pilot·로컬 전용 기록은 이전 검증 당시 상태이며 현재 완료 상태는 `CODEX_STATE.md`에 기록한다.

## 범위
기존 FE·인프라 브랜치에 종무형 130bec1까지 통합한 803a27e를 기준으로 한다. 로컬 검증·가공만 수행하며 서버 적재/활성화와 develop 병합 및 릴리스 배포는 별도다. 아래 완료 항목은 3단계 전체 완료를 뜻하지 않는다.

## 수정과 검증
- 배포 manifest에 남은 CRLF 메타파일 해시 3개를 Git LF 바이트 기준으로 정정했다. 압축 마스터는 변경하지 않았다. 생성 도구도 LF를 명시한다. 전체 배포 목록 검증 회귀 테스트 추가.
- FE 일정 저장 테스트는 현재+30분 출발을 선택하면서 도착을 오늘19:30으로 두어 늦은 시간 실행에서 실패했다. 도착일을 이틀 뒤로 명시해 정상 저장 시나리오를 유지했다. 앱 시간 검증은 완화하지 않았다. FE 전체122개 통과.
- 새 마스터 METRO-BUS-20260917-SEOUL-0902로 실제 관측72,820행/156노선 재매핑. 정확 일치69,848, 정류장쌍 없음587, 순서불일치2,385. 이전 정확68,500 대비1,348 증가. 노선 없음1,627→0. 정확 일치는 현재 마스터 구조 일치이며 과거 유효성 승인이 아니다.
- 기존 마스터에 포함된 (namespace,routeId)는 확장 후보에 중복 추가하지 않고 별도 검토 목록에 보존한다. 노선 존재를 정류장 순서 검증 완료로 처리하지 않는다.

## 입력과 출력
workbench `data_staging/recommendation-20260917` 아래 원본 traversal과 기존 주간·월간 daily.sqlite를 읽기 전용 재사용한다. 기존2단계 결과는 보존한다.
- 새 실제매핑: `stage3-bus-mapping/bd983d215f4cb90eb541`.
- 주간·월간 기준값: `stage3-bus-reference/edbc40a7c9b941d85267`. PID20676 종료0/COMPLETE. 주간5,026,765·월간20,817,894 일자키 매핑. 중복 추가 후보0/이미 존재4노선. 매핑과 기준값 두 묶음 모두 출력 체크섬 통과. 실제관측 표본충분 조건 미달67,178그룹이며 운영승인은 아니다.
- 검증: FE122개, 인프라·버스31개, 마스터 설정·배포2개, 서울 마스터 갱신2개 통과. 원본/이전 결과와 서버 상태 보존.

## 서버 계약 대조에서 확인한 미연결 사항
1. `BaselineRowsRequest.Row`는 weatherBucket과 p50/p80/p95를 필수로 요구하며 WeatherBucket은 DRY/RAIN/SNOW만 있다. 보유 시간대 평균을 이동시간 백분위로 복제하거나 날씨를 DRY로 꾸며 이 API에 넣을 수 없다. 날씨 독립 참고 기준값의 별도 저장·조회 계약이 필요하다. 원천 구분, 순서, 자료기간, 표본 수, 마스터 버전을 보존해야 한다.
2. 현재 일정 생성은 plannedDepartAt 필수다. 목표 도착만 입력하는 모드는 아직 BE 계약이 없다.
3. 알림 목록·상세 NotificationResponse에 evaluationId/validUntil이 없다. FCM에만 있는 값을 알림함 조회에서 복구할 수 없다.
4. 지하철 참고자료는 현행 운행일 검증이 없고 도로 승인매핑은0이다. 자동으로 실시간 시간표나 통제 근거로 승격하지 않는다.
