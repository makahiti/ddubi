# 교통 데이터 2단계 실행

## 범위
- 사용자 요청: 보유 자료 전체를 활용해 기준값·후보 마스터·도로 연결 결과를 만들고 적재를 준비한다.
- 서버 업로드/DB 적재/운영 활성화는 수행하지 않는다. BE 계약과 현행 유효성이 부족한 자료는 검토용 계약으로 구분한다.
- 독립 프로세스와 파일 로그를 사용한다. 네트워크 단절과 노트북 절전/종료는 다르며, 절전/종료 시 가공은 지속되지 않는다.

## 병렬 담당
- 버스: 기존 SQLite 일자별 값 재사용, 날짜·구간 키 중복/충돌 분리, 기준값 연결과 누락4노선 후보 조립. 실제관측과 시간대집계 분리.
- 지하철: 전국568패턴 검토용 마스터와 참고구간시간/배차정보 패키지. 현재 운행일/유효기간/provider ID를 생성하지 않음.
- 도로: 최초 후보탐색 방향필터와 occurrence 연속경로 검사 보강 후 전체 보유 형상 처리. 배치별 재시작.
- 통합 담당: 서로 다른 완료manifest 검증, 결과·로그·PID 인계 관리 및 최종 코드 통합.

## 검증 경계
- verify-transit-bundle.py가 초기 가공/버스/지하철/도로 입력 해시 형식을 지원하도록 보강. 테스트5개 및 기존 실제 산출물3개 무결성검사 통과.
- 무결성 검사는 출력이 선언된 체크섬과 같다는 뜻이다. 실제 입력의 현행 유효성, 운영 적합성, 서버 적용을 증명하지 않는다.

## 실행 인계
파트별 job.json에 PID·시작시각·명령/스크립트·stdout/stderr·출력경로를 기록한다. 완료manifest와 실패 exit code를 별도로 보존한다. 프로세스가 사라졌다는 이유만으로 완료 처리하지 않는다.
