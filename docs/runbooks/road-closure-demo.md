# 서울 버스 도로 통제 시연

이 기능은 실제 TOPIS 사고 판정의 정확도를 증명하는 기능이 아닙니다. 발표용 가짜 사건을
선택된 버스의 **검증된 서울 인접 정류장 구간**에 직접 연결합니다. 가짜 `roadLinkId`는
`DEMO-...`로 표시하며 실제 TOPIS 도로 링크 ID라고 주장하지 않습니다.

## 준비

1. 발표 환경의 `infra/.env`에 `DDUBI_DEMO_ROAD_CLOSURE_ENABLED=true`를 넣고
   Backend 컨테이너를 재생성합니다. 평소 기본값은 `false`입니다. 일반 환경에서
   켜거나 공용 `segment:status:*`/`road:incidents:*` 키를 직접 바꾸지 마세요.
2. 휴대폰 앱도 이번 변경 코드로 다시 빌드·설치합니다. 로그인 계정의 알림 설정을 켜고
   앱 알림 권한·유효한 FCM 기기 토큰을 확인합니다. 푸시가 꺼져 있으면 대안은 계산되지만
   알림은 `SUPPRESSED`로 기록되고 화면에 안내가 뜹니다.
3. 제목을 `[시연] 출근`처럼 `[시연]`으로 시작하게 하여 **서울 출발지 → 서울 도착지**
   일정을 등록합니다. 도착시각은 현재부터 3시간 이내로 잡습니다. 실제 길찾기 후보에
   서울 공식 ID로 매핑된 버스 중심 경로가 최초 계산의 최선이고, 그 버스 구간을 피하는 대안 경로가 모두
   있어야 합니다. 후보는 외부 길찾기 API에 따라 달라지므로 발표 장소·시각으로 먼저
   리허설하세요. 조건이 없으면 일반 최선 경로를 유지하며 가짜 통제를 만들지 않습니다.

## 화면 흐름

`일정 저장 → 서버 첫 계산(버스 경로를 지금 경로로) → 약 10초 뒤 서버가 스스로 시연 통제 저장
→ 저장된 후보 즉시 재평가 → 다른 경로 제안 → 본인에게 경로 변경 알림`

2026-09-25 부터 **상세 화면을 열지 않아도** 진행됩니다. 서버(`RoadClosureDemoAutoTrigger`)가 5초마다
"[시연]" 일정 중 저장한 지 10초가 지났고 첫 계산이 끝난 것을 찾아 한 번 통제를 겁니다. 첫 계산이
덜 끝났거나 다른 계산이 잠깐 붙잡고 있으면 5초 뒤 다시 해 보고, 일정·입력 버전마다 최대 6번까지만
합니다. 버스 위주 경로가 아니거나 우회 경로가 없으면 평소 일정처럼 둡니다. 상세 화면을 열어 두면
앱도 첫 결과를 본 10초 뒤 같은 요청을 보내 화면을 바로 새로 읽습니다(이미 걸렸으면 `ALREADY_APPLIED`,
알림은 한 번만).

실제 TOPIS 수집/매핑 검증이 아니라, 통제가 확인됐을 때 추천 엔진과 알림이 어떻게 반응하는지
보여주는 시연입니다. 다른 경로를 자동으로 선택하지 않고 제안으로 보여줍니다. 사용자가 실제 적용
여부를 결정합니다.

### 화면에서 보이는 것 (2026-09-26 기준: 시연 표시는 한 번씩만, 문구는 실제와 같다)

- **막는 단위는 도로다**: 막힌 버스 구간의 두 정류장 사이 도로를 막는다. 그 사이를 지나는 서울 버스는
  번호와 관계없이 모두 막힌다(Redis 키의 `stopPair`). 그래서 대안은 그 도로를 아예 지나지 않는 경로다.
  예전(2026-09-25)에는 145번 한 노선만 막아, 같은 도로를 3030·917번으로 가는 경로가 "새 경로" 로 나왔다.
  시연을 걸 수 있는지(대안 존재)도 같은 기준으로 판단한다.
- **막힌 구간 문장**: 막힌 두 정류장과 버스 번호로 실제 돌발 공지 같은 문장을 만든다. 같은 도로를 다른
  버스도 지나면 "등" 을 붙인다. 예: "신사역8번출구 → 신사역 구간 도로 통제로 145번 등 버스 운행에 차질이 있어요."
- **오늘의 이동 변수 · 도로 칸**: "[시연] " + 위 문장. 덧말("시연용 가상 통제")은 붙이지 않는다.
  같은 도로를 지나는 경로(번호만 다른 버스 포함)를 고르면 통제가 보이고, 다른 도로로 가는 경로를 적용하면
  원래 표시로 돌아간다.
- **교통 안내 카드**: 이름표 옆에 작은 "시연" 표시를 한 번만 붙인다. 문장에는 "[시연]" 을 붙이지 않는다.
  생성 AI 에는 위 문장, 실제 돌발과 같은 출처, "제안 경로는 이 통제 구간을 지나지 않아요" 를 보낸다.
  출처는 영문 코드 대신 "서울시 교통 돌발정보" 로 보인다(실제 사고도 같다).
- **경로 카드**: 막힌 "선택된 추천 경로" 에는 "통제 구간을 지나요" 표시와 안내 한 줄이 붙는다.
  "새로 제안된 경로" 카드에는 "15:55 도착 예상 · 통제 구간을 피해 가요" 와 **"이 경로로 바꾸기"** 단추가 있다.
  교통 안내 카드의 적용 단추는 같은 경로에서 출발 시각만 바뀌는 제안일 때만 "제안한 출발 시각으로 바꾸기" 로 나온다.
- **맨 위 결론 줄**: 원인이 확정된 통제·지연이면 상황에 따라 다르게 말하고, 시연이면 앞에 "[시연]" 이 붙는다.
  - 다른 경로를 제안할 때: "도로 통제를 피해 다른 경로로 안내해요."
  - 같은 경로, 여유 10분 안: "도로 통제가 예상돼 서둘러 나가는 게 좋아요."
  - 같은 경로, 여유 넉넉: "도로 통제가 예상되지만 제시간에 도착할 수 있어요."
  - 계획 출발이 지났지만 시간 안에 닿는다: "도로 통제가 예상돼 지금 바로 나가는 게 좋아요"
  - 늦는다: "도로 통제로 희망 도착 시간에 도착하기 어려울 것 같아요"
- **"이 일정에 맞춰" 카드**: 상황별 한 줄 — 새 경로 제안이 있으면 "새로 제안된 경로가 있어요", 도착 시간이
  지났으면 "도착 시간이 지난 일정이에요 · 다녀오셨다면 도착 완료를 눌러 주세요", 이동 중이면 "이동 중이에요".
- **푸시가 두 개 올 수 있다**: 시연이 보내는 "[시연] 145번 버스 경로에 도로 통제가 생겼어요"
  (본문 "신사역8번출구 → 신사역 구간이 통제돼요. 다른 경로를 확인해 주세요.")와, 기존 규칙이 보내는
  "[시연] 지금 경로가 막혔어요"(본문 "다른 경로로 가면 15:55 도착 예상 · 목표 16:30")다. 다른 경로로도 늦으면
  "제시간 도착이 어려울 수 있어요" 가 된다. 예전에는 막힌 경로에 도착 예정이 없어 "도착 시각을 계산하지 못했어요"
  가 나갔다. 추천 승인 전 단계라 기존 규칙 알림 본문 앞에는 "[검증용]" 이 붙는다(추천 승인 정책이라 그대로 둔다).
- **이동 예측 카드**: 일정 상세에서 보이지 않는다(개발자 옵션을 켜면 보인다). 맨 위 결론·이동 변수가
  같은 값을 보여준다.


## 저장과 격리

- Redis: `demo:topis:road-control:schedule:{scheduleId}` 한 키에 `source=DEMO_TOPIS`,
  `demo=true`, `inputRevision`, 가짜 `roadLinkId`, 공식 버스 `segmentId`, `blocked`,
  발생·만료시각을 저장합니다. TTL은 일정 도착시각 1시간 후까지이며 등록 시점부터
  최대 4시간입니다. 일정 수정으로 입력 버전이 바뀌면 이전 사건을 재사용하지 않습니다.
- MySQL: 기존 `schedule_evaluation`/추천 스냅샷에 재평가 결과와 후보를 저장합니다.
  알림 이력은 기존 `notification` 테이블에 저장합니다.
- 공용 Redis 교통 키, 실제 TOPIS Kafka 이벤트, 다른 사용자의 일정은 변경하지 않습니다.

시연이 안 되면 화면의 안내와 Backend 로그를 확인하세요. 특히 `READY`가 아닌 상태,
버스 중심 선택 경로/우회 후보 없음, 서울 매핑 없음, 3시간 초과 일정, Redis 장애,
FCM 토큰 또는 알림 권한 누락을 구분해야 합니다. `ALTERNATIVE_READY`는 대안 계산
완료이고, `notificationStatus=SENT`일 때만 휴대폰 전송 성공입니다.
