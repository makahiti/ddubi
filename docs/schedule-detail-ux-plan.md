# 일정 상세·홈 이동 예측 화면 개편 설계안 (2026-09-18, 구현 전)

ML 시험 적용 검증이 끝난 뒤 진행하기로 한 후속 작업이다. **아직 코드에 반영하지 않았다.**

## 1. 지금 무엇이 문제인가 (실기기 화면 기준)

일정 상세를 위에서부터 보면 순서가 이렇다.

1. 제목·날짜·장소 카드
2. 캐릭터 안내 그림
3. 예상 이동 시간(약 46분), 환승 정보, 주요 이동 수단
4. 추천 근거
5. 저장된 추천 경로 5개
6. 오늘의 이동 변수 4칸
7. **이동 예측 카드** ← 추천 출발시각이 여기 있다
8. 참고자료 준비 상태
9. 일정 수정·도착 완료·일정 취소

문제는 네 가지다.

- **가장 중요한 값이 가장 아래에 있다.** 사용자가 알고 싶은 것은 "몇 시에 나가야 하나"인데, 상단에는 "46분 걸린다"만 있고 출발 시각은 한참 스크롤해야 나온다.
- **시각이 너무 많다.** 이동 예측 카드에 사용자 입력 출발, 현재 계획 출발, 평가 목표 도착, 제안 출발, 예상 도착, 마지막 확인까지 최대 여섯 줄이 나온다. 실제로 필요한 것은 둘이다.
- **문구가 계산 과정을 설명한다.** "전체 이동시간의 구성요소가 완전히 확인되지 않았습니다", "대체 계산 사용: 일부 구간은 기본 경로 정보 사용" 은 무엇을 해야 하는지 알려주지 않는다. 상태 칩 "검증용"도 뜻이 전달되지 않는다.
- **홈과 상세가 같은 내용을 두 번 보여준다.** 홈 박스는 상세 요약을 밀도만 줄여 반복한다.

## 2. 개편 방향

| 영역 | 지금 | 바꿀 모습 |
|---|---|---|
| 상세 상단 | 소요시간만 | **결론 한 줄**: "오전 8시에 나가면 8시 43분 도착", 아래 작게 "일정 시작 17분 전 도착" |
| 확정 못 한 경우 | 카드 안에 긴 문구 | 상단에 "아직 출발시각을 확정하지 못했어요" + 부족한 것 한 줄 |
| 이동 예측 카드 | 시각 6줄 + 품질 문구 + 버튼 | **근거와 조작만**: 마지막 확인 시각, 믿을 만한 정도 한 줄, 버튼 3개 |
| 시각 표시 | 항상 6줄 | 기본 2줄(제안 출발·예상 도착), 나머지는 "자세히"로 접기 |
| 상태 칩 | "검증용", "갱신 필요" | 문장으로: "아직 시험 중인 예측이에요", "최신 결과를 다시 확인해 주세요" |
| 홈 박스 | 상세와 같은 내용 반복 | 한 줄 요약 + 누르면 상세로 이동 |
| 오늘의 이동 변수 | 네 칸 모두 "확인 필요" | 값이 없으면 통째로 숨기거나 한 줄로 |

## 3. 설계에서 먼저 정해야 할 것

- **확정 조건이 까다롭다.** 지금 추천이 확정되려면 검증 통과·전체 구성요소 확인·탐색 완료가 모두 필요해서, 상단에 시각을 크게 띄워도 대부분 "확정 못 함"이 뜬다. 상단 영역은 확정일 때와 아닐 때 **두 모드**를 모두 제대로 보여줘야 한다.
- **확정 못 했을 때 무엇이 부족한지 한 줄로** 말해야 한다. 지금은 부족한 정보가 174건씩 쌓여 나오는데, 사용자에게는 "일부 버스 구간의 실시간 정보가 부족해요" 한 줄이면 된다.
- **과거 평균 기반 참고값과 확정 추천을 섞지 않는다.** 지금 규칙(참고 추정은 별도 표기, 적용 버튼 비활성)은 유지한다.
- 개발자 진단은 지금처럼 분리해 두고 상단 요약에는 넣지 않는다.

## 4. 범위 밖

- 모델·예측값·서버 계약 변경 없음. 화면 구성과 문구만 다룬다.
- 추천 후보 노출 정책(최대 5개·중복 묶기)은 이미 적용됐다. 이 문서는 그 위쪽 영역을 다룬다.
- 서버 응답 크기(672KB) 최적화는 별도 성능 작업으로 따로 기록돼 있다.
