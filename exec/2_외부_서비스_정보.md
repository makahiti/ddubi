뚜비(DDUBI)가 쓰는 외부 서비스를 모두 적었다. 서비스마다 **무엇에 쓰는지, 어디에 설정하는지, 가입·신청할 때 무엇이 필요한지**를 정리했다.

- 기준: 2026-09-27, `develop` 브랜치(서버에 배포된 코드)
- 실제 키·비밀번호·토큰 값은 이 문서에 없다. 변수 **이름**만 적는다. 값은 서버의 `infra/.env`(권한 600), 앱의 `client/.env`, GitLab CI/CD 변수에만 둔다.
- 변수가 어느 파일에 들어가는지는 [1_포팅_매뉴얼.md](1_포팅_매뉴얼.md)의 "환경 변수" 절에 있다.

## 1. 소셜 로그인

### 1-1. 카카오 (카카오 개발자센터 developers.kakao.com)

로그인, 지도, REST API를 **하나의 카카오 앱**으로 쓴다. 인가 코드와 토큰이 앱 단위로 발급되기 때문이다.

가입·등록 순서:

1. 내 애플리케이션 → 애플리케이션 추가.
2. 앱 키 네 가지를 확인한다: 네이티브 앱 키, JavaScript 키, REST API 키, 숫자 앱 ID.
3. 플랫폼 등록
   - Android: 패키지명 `com.ssafy.ddubi`, **릴리스 서명 키의 키 해시**.
   - Web: 사이트 도메인 `https://j15e202.p.ssafy.io`, 로컬 개발은 `http://localhost:3001`.
4. 카카오 로그인 활성화. 동의 항목은 닉네임과 카카오계정(이메일)이 필요하다. 코드가 `kakao_account.email`, `profile.nickname`을 읽는다.
5. 카카오 로그인 → 보안에서 Client Secret 코드를 켰다면 그 값을 `KAKAO_CLIENT_SECRET`에 넣는다. 켜 놓고 값을 안 넣으면 `KOE010` 오류가 난다.

어디에 넣나:

| 값 | 변수 | 위치 |
|---|---|---|
| 네이티브 앱 키 | `KAKAO_NATIVE_APP_KEY` | `client/.env` (앱 빌드 때 `--dart-define-from-file`) |
| JavaScript 키 | `KAKAO_JAVASCRIPT_KEY` | `client/.env` (웹 빌드) |
| REST API 키 | `KAKAO_REST_API_KEY` | 서버2 `infra/.env`(백엔드), 서버1 `infra/.env`(스파크) |
| 숫자 앱 ID | `KAKAO_APP_ID` | 서버2 `infra/.env` (앱이 보낸 토큰의 앱 ID 대조) |
| Client Secret | `KAKAO_CLIENT_SECRET` | 서버2 `infra/.env` (켰을 때만) |

- 안드로이드 로그인 콜백 스킴은 `kakao{네이티브 앱 키}://oauth`이며 `AndroidManifest.xml`에 이미 들어 있다.
- 앱은 카카오 토큰을 `POST /api/v1/auth/oauth/token`으로 백엔드에 보낸다.

### 1-2. 구글 (Google Cloud Console → API 및 서비스 → 사용자 인증 정보)

1. OAuth 동의 화면을 만든다.
2. **웹 애플리케이션** OAuth 클라이언트를 만든다. 이 클라이언트 ID가 백엔드의 `GOOGLE_CLIENT_ID`이면서 앱의 `GOOGLE_WEB_CLIENT_ID`다. 클라이언트 보안 비밀은 `GOOGLE_CLIENT_SECRET`.
3. **Android** OAuth 클라이언트를 만든다. 패키지 `com.ssafy.ddubi`와 **빌드에 쓴 서명 키의 SHA-1**을 넣는다.
4. 앱은 ID 토큰을 `POST /api/v1/auth/oauth/id-token`으로 보낸다. 백엔드는 토큰의 대상(aud)이 `GOOGLE_CLIENT_ID`인지 확인한다.

### 1-3. 네이버 (네이버 개발자센터 developers.naver.com)

1. Application 등록 → 사용 API "네이버 로그인".
2. 제공 정보: 이메일, 별명. (이메일을 빼면 값이 오지 않는다.)
3. 서비스 URL `https://j15e202.p.ssafy.io`, Callback URL `https://j15e202.p.ssafy.io/oauth/naver`.
4. 앱에는 공개 값인 `NAVER_CLIENT_ID`, `NAVER_REDIRECT_URI`만 넣는다. `NAVER_CLIENT_SECRET`은 서버2에만 둔다.
5. 앱은 인가 코드와 확인한 state를 `POST /api/v1/auth/oauth`로 보낸다.

> 소셜 로그인은 **안드로이드 앱**에서 동작한다. 웹에서 구글·네이버 버튼을 누르면 안드로이드 안내가 나온다. 웹과 앱 모두 이메일 회원가입·로그인은 된다.

## 3. Firebase Cloud Messaging (푸시 알림)

- Firebase 프로젝트: `ddubi-85d2b` (이미 만들어 둔 것을 쓴다).
- Android 앱 등록: 패키지 `com.ssafy.ddubi`. 알림 채널 ID는 `ddubi_default`.
- 앱: 콘솔에서 받은 `google-services.json`을 `client/android/app/`에 둔다. **Git에 커밋하지 않는다.**
- 백엔드: 프로젝트 설정 → 서비스 계정 → 새 비공개 키(JSON) 발급 → base64로 바꿔 GitLab CI/CD 변수 `FIREBASE_CREDENTIALS_BASE64`에 넣는다. 배포 때 서버2 `infra/.env.backend`로 들어간다. 파일로 줄 때는 `FIREBASE_CREDENTIALS_PATH`.
- 백엔드는 `firebase-admin` 9.4.1 라이브러리로 직접 보낸다(별도 알림 서버 없음).
- 자격 증명이 없으면 알림은 보내지 않고 기록만 남긴다.

## 4. Gmail SMTP (회원가입 인증 메일)

- 호스트 `smtp.gmail.com`, 포트 587, STARTTLS.
- 구글 계정에서 2단계 인증을 켜고 **앱 비밀번호(16자리)** 를 만든다. 그 값을 `MAIL_PASSWORD`에, 계정 주소를 `MAIL_USERNAME`에 넣는다.
- 값은 GitLab CI/CD 변수로 두고, 배포 때 서버2 `infra/.env.backend`로 들어간다.
- 교육장 망이 587을 막으면 `smtp.naver.com`으로 바꿀 수 있다.
- 값이 비어 있으면 메일은 보내지 않고 로그에만 남긴다.

주의:

- `BUS_API_KEY_A`와 `BUS_API_KEY_B`는 **버스 도착과 버스 위치를 둘 다 승인받은 서로 다른 키**여야 한다. B가 없으면 A만으로 돈다.
- 서울 열린데이터광장 인증키는 **실시간 지하철 전용 키**와 **일반 인증키** 두 종류다. 따로 신청한다.
- 서울 버스·열린데이터 API는 HTTP만 된다. 돌발·TOPIS 공지는 XML만 준다.
- 하루 호출 상한은 수집기 안의 제한기가 지킨다(`*_DAILY_BUDGET*` 변수). 이 값은 우리가 정한 내부 상한이지 제공처의 공식 한도가 아니다. 공식 한도는 각 사이트의 활용신청 상세에서 확인한다.
  - 버스: 키 하나당 하루 9,000번
  - 실시간 도시데이터: 하루 40,000번
  - TOPIS 공지: 하루 500번
  - 기타 수집기 공통: `API_DAILY_LIMIT=900`

## 7. 인프라·운영 서비스

### Let's Encrypt (HTTPS 인증서)
- 서버2의 `certbot` 컨테이너(`certbot/certbot:v2.11.0`)가 12시간마다 확인해 만료 30일 전이면 자동 갱신한다.
- **처음 한 번만** 손으로 발급한다(nginx를 1분쯤 멈춘다). 방법은 [1_포팅_매뉴얼.md](1_포팅_매뉴얼.md) "HTTPS 인증서" 절.
- 변수: `PUBLIC_DOMAIN`(예: `j15e202.p.ssafy.io`), `TLS_EMAIL`(만료 안내 받을 주소).

### Mattermost 수신 웹훅 (운영 알림)
- 채널 → 통합 → Incoming Webhooks에서 만든다.
- Grafana 알림 규칙 11개와 `infra/scripts/daily-brief.py`(매일 09:30·17:00 서버 상황 요약)가 이 웹훅으로 보낸다.
- 변수: `GRAFANA_ALERT_WEBHOOK_URL` (서버1·서버2 `infra/.env`에 같은 값).

### SSAFY GitLab (lab.ssafy.com) CI/CD
- 파이프라인: `.gitlab-ci.yml`. 러너는 서버2의 단독 컨테이너 `gitlab-runner`(docker executor)다.
- CI/CD 변수(설정 → CI/CD → 변수)
  - `DEPLOY_SSH_KEY` (파일, 보호): 배포 잡이 서버에 접속할 키
  - `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`
  - `FIREBASE_CREDENTIALS_BASE64`
- 보호 변수는 보호 브랜치에서만 주입된다. `develop`을 보호 브랜치로 둔다.
- 서버의 `git pull`은 읽기 전용 Deploy Token을 넣은 HTTPS 주소를 쓴다.
