# 4. 시연 시나리오

뚜비(DDUBI)는 **도착 일정을 등록하면, 실시간 교통 상황에 맞춰 언제 어떤 경로로 나가야 하는지 계속 다시 계산해 알려 주는** 대중교통 일정 비서다.

이 문서는 시연 순서대로 **화면마다 무엇을 누르는지(위치 포함)와 무엇이 보이는지**를 적었다.

- 기준: 2026-09-27, `develop` 브랜치 앱·서버
- 기기: 안드로이드 휴대폰(릴리스 APK). 웹(`https://j15e202.p.ssafy.io`)과 다른 점은 5절.
- 소요 시간: 약 7~8분 (핵심 장면 1~7은 약 5분)

## 1. 시연 흐름 한눈에 보기

```text
① 로그인 → ② 홈 → ③ 일정 등록 → ④ 추천 출발 시각·경로 확인
   → ⑤ (10~15초 뒤) 도로 통제 발생 → 화면이 스스로 바뀌고 푸시 알림 도착
   → ⑥ 알림 눌러 확인 → ⑦ "이 경로로 바꾸기" → ⑧ 이동 안내 시작
   → ⑨ 부가 기능(브리핑·이동 기록·리포트) → ⑩ (선택) 데이터 파이프라인 모니터링
```

> ⑤의 도로 통제는 **발표용 가짜 사건**이다. 실제 서울시 돌발정보가 들어왔을 때 추천 엔진과 알림이 어떻게 반응하는지 보여 준다. 가짜 사건은 해당 일정에만 걸리고, 공용 교통 자료나 다른 사용자에게는 영향이 없다. 화면에도 "시연" 표시가 붙는다.

## 2. 사전 준비

### 2-1. 서버 (서버2)

| 확인 | 명령 | 기대값 |
|---|---|---|
| 시연용 도로 통제 스위치 | `docker exec backend printenv DDUBI_DEMO_ROAD_CLOSURE_ENABLED` | `true` |
| 평가 결과 자동 알림 | `docker exec backend printenv DDUBI_AUTO_NOTIFY_ENABLED` | `true` |
| 검증용 결과 알림 | `docker exec backend printenv DDUBI_SHADOW_PREVIEW_NOTIFY_ENABLED` | `true` |
| 서버 전체 점검 | `bash ~/S15P21E202/infra/scripts/checks/server2.sh \| column -t -s'\|'` | `FAIL` 없음 |

- 스위치가 꺼져 있으면 서버2 `infra/.env`에 `DDUBI_DEMO_ROAD_CLOSURE_ENABLED=true`를 넣고 백엔드만 다시 만든다.

  ```bash
  cd ~/S15P21E202/infra
  docker compose -f docker-compose.yml -f docker-compose.server2.yml --profile serving up -d --no-deps --force-recreate backend
  ```

### 2-2. 휴대폰

1. 최신 릴리스 APK를 설치한다(포팅 매뉴얼 3-2).
2. 발표 계정으로 로그인해 둔다. (이메일 가입 또는 카카오·구글·네이버)
3. **알림 권한 허용**: 앱 → 하단 다섯 번째 탭 "더보기" → 아래쪽 권한 카드 → **"알림 권한"이 "허용됨"** 인지 확인.
4. 위치 권한도 "허용됨"이면 "현재 위치로 설정"을 쓸 수 있다(필수 아님).
5. 방해 금지 모드를 끄고, 화면 녹화를 켜 둔다(장애 대비 녹화본).

### 2-3. 시연 일정 조건 (하나라도 어긋나면 도로 통제가 걸리지 않는다)

| 조건 | 값 |
|---|---|
| 제목 | **`[시연]`으로 시작** (반각 대괄호, 앞에 공백 없음). 예: `[시연] 오후 수업` |
| 출발지·도착지 | **둘 다 서울** |
| 도착 희망 시간 | **지금부터 3시간 안** (권장: 지금 + 1시간) |
| 출발 예정 시간 | 지금 + 20~30분 (이미 지난 시각이면 "이 경로로 바꾸기"가 안 눌린다) |
| 새 일정 | 통제는 **일정마다 한 번**. 다시 하려면 새 일정을 만든다 |
| 경로 | 첫 계산의 최선 경로가 **서울 버스 위주**여야 하고, 그 도로를 피하는 다른 경로가 있어야 한다 |

- **리허설로 확인된 구간: 출발지 `서울역` → 도착지 `숙명여자대학교 제1캠퍼스 정문`** (262번·용산04 버스, 약 13분). 2026-09-25 23:11 리허설에서 통제·제안·알림 2건 발송까지 확인했다.
- 다른 후보: `손기정기념관` → `이원일식탁` (262·740번, 약 26분).
- 안 되는 예: `서울역` → `멀티캠퍼스 역삼` (지하철이 더 길어 버스 위주 경로가 아님).
- 경로 후보는 카카오 길찾기 결과에 따라 달라지므로 **발표 시각과 비슷한 시간에 한 번 리허설**한다.

## 3. 화면 구성 (누를 위치)

### 하단 탭 (왼쪽부터)

| 위치 | 탭 | 내용 |
|---|---|---|
| 첫 번째 | **일정** | 전체 일정 달력, 오른쪽 아래 **＋**(일정 등록) |
| 두 번째 | **경로** | 출발·도착·시각을 넣고 바로 경로 평가 |
| 세 번째 (가운데) | **홈** | 인사, 다음 일정 결론 한 줄, 오늘의 일정 |
| 네 번째 | **알림** | 알림함 (종 아이콘에 안 읽은 개수) |
| 다섯 번째 | **더보기** | 계정, 브리핑, 이동 기록, 저장 장소, 권한, 로그아웃 |

### 일정 상세 화면 (위에서 아래 순서)

| 순서 | 영역 | 보이는 것 |
|---|---|---|
| 1 | 상단 바 | 일정 제목, 그 아래 "날짜 시각 도착 · 장소" |
| 2 | **결론 줄** | "추천 출발 시각" + 큰 시각 "**15:40** 에 나가세요", 작은 칸 "도착 예정", "여유" |
| 3 | **이 일정에 맞춰** | 상황 한 줄 (예: "지금 경로 그대로 가면 돼요.") |
| 4 | **현재 선택 경로** | 예상 이동 시간, 예상 요금, 주요 변동 요소 |
| 5 | **추천 경로** | 선택된 경로 카드 (+ 제안이 있으면 "새로 제안된 경로" 카드와 **"이 경로로 바꾸기"**) |
| 6 | **교통 안내 카드** | "AI 교통 안내" 이름표, 이유 문장, 흰 상자(경로 요약·도착 예정·요금·단계별 경로·교통 영향·"실시간 정보 기준 HH:MM"), 버튼 "다시 계산", **"이동 안내 시작"** |
| 7 | **오늘의 이동 변수** | 날씨 / 혼잡도 / 도로 통제 / 지하철 네 줄, "HH:MM 기준" |
| 8 | 맨 아래 버튼 | "일정 수정", "도착 완료", 빨간 "일정 취소" |

## 4. 시연 순서

### 장면 1. 앱 실행과 로그인 (약 20초)

| 누를 곳 | 보이는 것 | 설명할 말 |
|---|---|---|
| 앱 아이콘 | 흰 화면에 뚜비 로고 → (처음 설치면) 소개 4장 | "뚜벅이의 비서, 뚜비입니다." |
| 소개 화면 오른쪽 아래 **→** 세 번, 마지막 장에서 한 번 더 (또는 오른쪽 위 **"건너뛰기"**) | 소개: "중요한 일정, 놓치지 않게 도와드려요" → "실시간 이동 변수를 한눈에 확인해요" → "여러 변수를 반영해 출발 시간을 추천해요" | 서비스가 하는 일 세 가지 |
| 로그인 화면: 이메일·비밀번호 입력 → **"로그인"** (또는 "또는" 아래 원형 아이콘: 왼쪽 노란 **K** 카카오, 가운데 **G** 구글, 오른쪽 초록 **N** 네이버) | 홈 화면 | 소셜 로그인 세 종류 지원 |

> 이미 로그인해 두었으면 앱이 바로 홈으로 열린다. 이 장면은 건너뛰어도 된다.

### 장면 2. 홈 화면 (약 20초)

| 누를 곳 | 보이는 것 | 설명할 말 |
|---|---|---|
| (하단 가운데 **홈**) | 위쪽 "안녕하세요! 🌱", 시간대별 인사 카드, **"다음 일정 · 제목 · 시각 도착"** 한 줄, 날짜 줄 "‹ 9월 27일 (토) ›", "오늘의 일정" 목록 | "앱을 열면 다음 일정에 언제 나가야 하는지가 가장 먼저 보입니다." |

### 장면 3. 일정 등록 (약 1분)

| 순서 | 누를 곳 | 입력·보이는 것 |
|---|---|---|
| 1 | 하단 **첫 번째 탭 "일정"** → 화면 **오른쪽 아래 ＋** | "일정 등록" 화면, "어디서 출발해서 어디로 가시나요?" |
| 2 | **일정 제목** 칸 | `[시연] 오후 수업` 입력 |
| 3 | **출발지** 칸 → "출발지 검색" 창 | `서울역` 검색 → 결과 **서울역** 누르기 |
| 4 | **출발 예정 시간**의 날짜 버튼·**시각 버튼** | 시각 버튼을 **꼭 한 번 눌러** 지금 + 20~30분으로 맞춘다. (안 누르면 저장할 때 "출발 예정시각을 직접 확인해 주세요."가 뜬다) |
| 5 | **도착지** 칸 → 검색 창 | `숙명여자대학교` 검색 → **숙명여자대학교 제1캠퍼스 정문** 누르기 |
| 6 | **도착 희망 시간** 시각 버튼 | 지금 + 1시간으로 맞춘다 (기본값 19:30은 3시간을 넘을 수 있으니 반드시 바꾼다) |
| 7 | **중요도** 카드 | "일반" / "중요" 중 하나 (예: "중요") |
| 8 | (선택) **막차 고려** 스위치 | 끔 |
| 9 | 맨 아래 **"저장하기"** | 저장되면 **일정 상세 화면이 자동으로 열린다** |

설명할 말: "지도 앱을 한 번 검색하는 게 아니라, 이 일정이 끝날 때까지 서버가 계속 관리합니다."

> 홈 화면의 "일정 추가"로 저장하면 상세 화면으로 가지 않고 홈으로 돌아온다. 시연은 **일정 탭의 ＋** 로 한다.

### 장면 4. 추천 출발 시각과 경로 확인 (약 1분)

| 누를 곳 | 보이는 것 | 설명할 말 |
|---|---|---|
| (기다림, 몇 초) | 회색 뼈대 화면 → 결론 줄 "추천 출발 시각을 계산하고 있어요." → 계산 완료 | 서버가 카카오 경로 후보를 받아 실시간 자료로 다시 계산 |
| 화면 맨 위 **결론 줄** | "추천 출발 시각" + "**15:40** 에 나가세요", "도착 예정 15:55", "여유 N분" | "몇 시에 나가야 하는지 한 줄로 알려 줍니다." |
| 아래로 밀기 → **추천 경로** | "선택된 추천 경로" 카드(버스 262번 등) | |
| 아래로 밀기 → **교통 안내 카드** | "AI 교통 안내" 이름표와 이유 문장, 흰 상자의 단계별 경로·요금·"실시간 정보 기준" 시각 | "생성형 AI가 지금 교통 상황을 쉬운 문장으로 풀어 줍니다. 계산 자체는 서버 규칙이 하고, AI는 설명만 합니다." |
| 아래로 밀기 → **오늘의 이동 변수** | 날씨 / 혼잡도 / 도로 통제 / 지하철 네 줄 | "수집 파이프라인이 모은 실시간 자료입니다. 자료가 없으면 '확인 안 됨'이라고 솔직하게 보여 줍니다." |

### 장면 5. 도로 통제 발생 → 화면이 스스로 바뀜 (약 1분)

첫 결과가 보이고 **약 10~15초 뒤**, 서버가 이 일정의 버스 도로에 발표용 통제를 건다. 사용자가 아무것도 누르지 않아도 화면이 새로 그려진다.

| 영역 | 바뀐 모습 |
|---|---|
| 맨 위 결론 줄 | "**[시연] 추천 출발 시각**" + 설명 "**도로 통제를 피해 다른 경로로 안내해요.**" |
| 이 일정에 맞춰 | "**새로 제안된 경로가 있어요.**" / "아래 경로 카드에서 비교하고 바꿀 수 있어요." |
| 추천 경로 — 선택된 경로 카드 | 빨간 "**통제 구간을 지나요**" 표시, "이 경로는 지금 통제로 막혔어요. 아래 새 경로를 확인해 주세요." |
| 추천 경로 — 새 카드 | "**새로 제안된 경로**" + 파란 "제안" 표시 + "15:55 도착 예상 · 통제 구간을 피해 가요" + **"이 경로로 바꾸기"** |
| 교통 안내 카드 | 이름표 옆 작은 "시연", 표시 "다른 경로 제안", 빨간 교통 영향 줄 "**서울역 → ○○ 구간 도로 통제로 262번 등 버스 운행에 차질이 있어요.**" (출처: 서울시 교통 돌발정보) |
| 오늘의 이동 변수 · 도로 통제 | "[시연] ○○ → ○○ 구간 도로 통제로 …" |

동시에 휴대폰에 **푸시 알림이 최대 2개** 온다.

| 순서 | 제목 | 본문 |
|---|---|---|
| 1 | **[시연] 262번 버스 경로에 도로 통제가 생겼어요** | ○○ → ○○ 구간이 통제돼요. 다른 경로를 확인해 주세요. |
| 2 | **[시연] 지금 경로가 막혔어요** | [검증용] 다른 경로로 가면 HH:MM 도착 예상 · 목표 HH:MM |

설명할 말: "실제 서울시 돌발정보가 들어오면 이렇게 됩니다. 등록해 둔 경로가 막히면 서버가 스스로 다시 계산해 다른 경로를 찾고, 휴대폰으로 알려 줍니다. 경로를 멋대로 바꾸지 않고 **제안**만 하고, 바꿀지는 사용자가 정합니다."

> 알림 본문 앞 "[검증용]"은 추천 모델이 아직 운영 승인 전이라 붙는다. 숨기지 않고 그대로 보여 준다.

### 장면 6. 알림 확인 (약 30초)

| 누를 곳 | 보이는 것 |
|---|---|
| 휴대폰 화면 위에서 아래로 내려 **푸시 알림** 누르기 | "알림 상세" 화면: 알림 종류·받은 시각·제목·본문, "지금도 유효한가요?" 칸 ("지금 최신 계산과 같은 내용이에요.") |
| 아래 **"연결된 일정 보기"** | 방금 그 일정의 상세 화면으로 이동 |

- 알림을 놓쳤으면 하단 **네 번째 탭 "알림"** → 알림함의 **"전체"** 칩에서 찾는다. (시연 알림은 "지연 안내" 칩에는 나오지 않는다.)
- 설명할 말: "알림을 누르면 옛 결과가 아니라 그 일정의 최신 계산으로 바로 들어갑니다."

### 장면 7. 제안 경로로 바꾸기 (약 30초)

| 누를 곳 | 보이는 것 |
|---|---|
| 일정 상세 → **추천 경로**의 "새로 제안된 경로" 카드 안 **"이 경로로 바꾸기"** | 아래 알림줄 "**제안한 경로로 바꿨어요.**" → 결론 줄의 출발 시각과 경로 카드가 새 경로로 바뀐다 |
| 아래로 밀기 → **오늘의 이동 변수 · 도로 통제** | 통제를 피하는 경로라 원래 표시로 돌아간다 |

- 카드의 버튼이 아닌 부분을 누르면 "경로 상세"(지도와 경로선)가 열린다. 지도를 보여 줄 때 쓴다.
- 통제는 일정마다 한 번이라, 바꾼 경로에 다시 통제가 걸리지 않는다.

### 장면 8. 이동 안내 (약 30초)

| 누를 곳 | 보이는 것 |
|---|---|
| 교통 안내 카드의 **"이동 안내 시작"** | "출발 안내" 화면: 이동 순서(도보 → 버스 → 도보) |
| 아래 **"출발했어요"** | 제목이 "이동 중"으로, "남은 이동 순서" 표시. 출발 뒤에는 실제 출발 시각 기준으로 다시 계산한다 |
| (선택) **"도착했어요"** | 결과 "여유 있게 도착했어요" / "빠듯하게 도착했어요" / "목표 시각을 넘겨 도착했어요" |

> "출발했어요"를 누른 일정은 더 이상 시연 통제 대상이 아니다. 이 장면은 **마지막**에 한다.

## 6. 문제가 생겼을 때

## 7. 시연 뒤 정리

1. 발표가 끝나면 서버2 `infra/.env`의 `DDUBI_DEMO_ROAD_CLOSURE_ENABLED`를 `false`로 바꾸고 백엔드를 다시 만든다(2-1절 명령).
2. 가짜 통제는 일정 도착 시각 1시간 뒤 저절로 사라진다(Redis 키 `demo:topis:road-control:schedule:{일정번호}`). 공용 교통 자료는 처음부터 건드리지 않는다.
3. 시연 일정은 일정 상세 맨 아래 빨간 **"일정 취소"** 로 정리할 수 있다.
